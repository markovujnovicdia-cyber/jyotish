# Native/Python numerical parity

The oracle is the unchanged `OriginalPython/core` implementation. No reference
formulas or expected results were rewritten to make a native test pass.

Regenerate fixtures from the repository root:

```sh
PYTHONDONTWRITEBYTECODE=1 /workspace/.venvs/jyotish/bin/python scripts/generate_parity_fixtures.py
swift test --package-path Packages/JyotishCore
```

The generator requires the Python project dependencies. It uses four synthetic
birth inputs (Europe/Zagreb, Australia/Sydney, Asia/Kolkata, America/New_York),
never the supplied persons database. Dates span 1977–2000, both hemispheres,
positive and negative longitudes, and different birth times. Five annual charts
include the 2025 and 2026 reference cases; each has all twelve monthly returns.

`PythonParity.json` records 4 natal charts, 5 annual charts, 60 monthly charts,
full mahadasha sequences and five active dasha levels. XCTest compares:

- All nine planetary longitudes, daily speeds, retrograde flags, signs, degrees,
  nakshatras/padas/lords, and ascendant.
- D1, D7, D9, D10 and D12 for all planets and the ascendant.
- Natal Arudha Lagna, Upapada, Darapada, Bhrigu Bindu, Gulika and the separate
  fixed-ghatika Mandi method, including horizon-period metadata.
- Annual return/next-return times, completed years, Muntha, actual solar
  day/night status, all twenty sahams and all Mudda periods.
- All five Varsheshwara candidates, eligibility, rounded scores, each of the
  five unrounded Pancha Vargiya Bala components, and the selected winner.
- Annual Ithasala/Isarapha geometry, orb and actual-speed applying/separating
  flags, including relative speeds.
- All sixty Masa Pravesha charts, special points and precise return times
  against the original minute-truncated display timestamp.

Angle tolerance is **1e-7 degree** (0.00036 arcsecond), speed tolerance is
**5e-8 degree/day** (0.00018 arcsecond/day). End-to-end dasha boundaries allow 100 microseconds for inherited astronomical
last-bit differences, binary epoch arithmetic and Python `timedelta` rounding. Chart
Julian-day comparisons use 1e-9 day; annual human timestamps allow 0.1 second.
The solver's original angular stopping threshold remains 1e-6 degree.

Separate `TajikaReference.json` tests cover 120 aspect cases, 504 numerical
strength cases, 252 selected-pair yoga cases plus global conditions, and 12
candidate-election cases generated by unmodified Python. Test run status and
platform coverage belong in `XCODE_VALIDATION.md`; fixtures by themselves are
not evidence that a test suite executed.

## Ephemeris backend difference

Both parity runtimes use **Swiss Ephemeris C 2.10.03**, Lahiri ayanamsha,
sidereal ecliptic longitude, Mean Rahu and Whole Sign houses. The native app
bundles `sepl_18.se1` and `semo_18.se1`; the generator selects those exact files.
SHA-256 provenance is embedded in fixture metadata.

The imported Python installation had no Swiss `.se1` data files. Its
`FLG_SWIEPH` calls therefore fell back to Moshier. The native wrapper requires
Swiss-file results and reports an error if they cannot be used. Consequently,
comparing the new native app with the old no-data Python installation is **not**
a comparison of identical numerical backends.

Measured maximum longitude differences at the same nine natal/annual instants
(4 natal + 5 annual), Swiss files versus original Moshier fallback:

| Body | Maximum absolute difference (arcseconds) |
| --- | ---: |
| Sun | 0.032377 |
| Moon | 1.131305 |
| Mercury | 0.054139 |
| Venus | 0.164173 |
| Mars | 0.095220 |
| Jupiter | 0.385431 |
| Saturn | 0.152809 |
| Mean Rahu / Ketu | 0 |

The largest measured daily-speed difference is 0.000146475 degree/day (Moon).
These are measurements of the selected fixtures, not global error bounds.

unchanged in all five cases. These backend differences are reported separately
from formula-port parity; no tolerance was widened to hide them.

## Deliberate fixes and retained source conventions

1. **Late-month solar-return bracketing:** Python clamps the birthday guess to
   day 28 and searches only ±3 days without confirming that the target is
   bracketed. For birth `1985-01-31T12:00:00Z`, return year 2026, original Moshier
   Python returns `2026-01-31T12:00:00Z` with a −0.528868036991° solar residual.
   The verified root is about `2026-02-01T00:30:30.995Z`. Native retains the
   original bisection where the bracket is valid, otherwise expands the search
   and verifies the same 1e-6° residual. The correction has a dedicated test.
2. **Monthly display precision:** Python drops the seconds from its returned
   Masa `datetime`, while computing the chart at the full Julian day. Native
   returns the actual solver instant. Tests compare identical charts and check
   that truncating the native timestamp reproduces Python's display minute.
3. **Birth calendar:** The full Python UI derives birthday/year from the
   person's local date. The old HTTP bridge used the UTC date. Native takes the
   selected IANA birth timezone, preserving full-Python behavior at local
   midnight/New Year rather than the old bridge's UTC shortcut.
4. **Gulika/Mandi:** The original minute-truncated horizon-event convention and
   weekday handling are retained. Mandi remains a distinct fixed-ghatika
   alternative; it is not silently relabeled as seasonal Gulika. Missing polar
   sunrise/sunset is reported, not replaced with invented values.
5. **Bhrigu Bindu:** Python's code uses the forward Rahu→Moon arc even though
   an introductory comment calls it the shorter arc. Native preserves the
   implemented forward-arc formula.
6. **Nakshatra boundaries:** Native reproduces Python floating floor-division
   behavior at representable boundaries, including `40 // (360/27) == 2`.
   The port does not silently switch to a different boundary convention.
7. **Tajika speed conventions:** Annual aspects use actual Swiss daily speeds.
   The existing selected-pair yoga module uses signed mean speeds. Its
   Isarapha predicate includes exact/stationary aspects via `!isApplying`,
   while annual relations explicitly distinguish applying/exact/separating.
   Nakta/Yamaya helper detection requires both aspects within orb but does not
   additionally require applying, despite prose mentioning Ithasala. Native
   preserves these differences and labels the legacy mean-speed convention.
8. **Varsheshwara source tables:** The imported Egyptian Hadda table and
   triplicity table are retained. This verifies computational parity with the
   selected source, not independent historical authority for the Hadda table.

9. **Canonical angle normalization:** adding 360 to a negative subnormal
   floating-point number can round to exactly 360. Native maps that equivalent
   circular endpoint back to 0, avoiding an out-of-bounds thirteenth-sign lookup.
   This numeric boundary hardening has a regression test; ordinary reference
   longitudes are unchanged.

No interpretive prose is part of the native calculation models or these
fixtures. The original Python tree remains unchanged as the numerical oracle.

## macOS / Linux speed comparison (2026-11-02)

The real [macOS CI run 41394769942](https://github.com/markovujnovicdia-cyber/jyotish/actions/runs/41394769942)
reported ten planetary-speed differences above the original 1e-8 degree/day
tolerance. The largest was **2.2188387127641818e-8 degree/day** for Mercury.
Those were the first published diagnostics; GitHub limits error annotations per step, so they did not establish that every other assertion passed.
The original fixture values, astronomical code and calculation flags are unchanged.

Swiss SPEED includes cancellation-sensitive finite-difference corrections:
`swi_get_ayanamsa_with_speed` subtracts angles over 0.001 day, and `swi_nutate`
subtracts near-equal vectors over 0.0001 day. Platform floating-point/library
evaluation differences can be amplified in these terms. This is a consistent
numerical explanation, not a proven diagnosis of one particular FMA operation.

The planetary-speed comparison now allows **5e-8 degree/day**, about 2.25 times
the largest observed discrepancy and 0.00018 arcsecond/day. Longitude tolerance
remains 1e-7 degree; exact discrete comparisons remain exact. Annual relation relative-speed comparison allows 1e-7 degree/day, propagating
the sum of two per-velocity 5e-8 budgets.
These are comparison tolerances for this sample, not global ephemeris accuracy
bounds, and no expected values were regenerated to conceal a failure.

A subsequent [macOS run 41395192602](https://github.com/markovujnovicdia-cyber/jyotish/actions/runs/41395192602)
reported relative-speed differences up to 2.218e-8 degree/day and end-to-end
mahadasha timestamp differences about 30 microseconds. For example, the native
Unix boundary 1356520109.4746819 differs from the Python 1356520109.474652 by
29.8 microseconds. Tiny Moon-longitude last bits are amplified by the multi-year
first-dasha balance calculation, in addition to binary Date/timedelta rounding.
The comparison allowance is now 100 microseconds; pure-period exact coverage,
chronology, selected lords and half-open interval checks remain in place.
Fixtures and production calculations have not been rewritten. The CI reporter
now includes a bounded complete failure summary so annotation limits cannot
conceal later categories of failure.
